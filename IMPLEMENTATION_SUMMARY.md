# Maintenance Hub Backend - Registration Implementation Summary

## Overview
Successfully implemented the user registration backend for the Maintenance Hub system based on the API documentation. The system supports three user roles: **CUSTOMER**, **TECHNICIAN**, and **ADMIN**.

---

## ✅ What Was Implemented

### 1. **Database Entities**
Created JPA entities following the ERD specifications:

#### User Entity (`User.java`)
- Primary user table shared by all three roles
- Fields: id, name, email, phoneNumber, password, role, isVerified, isBlocked, failedLoginAttempts
- Supports three roles: CUSTOMER, TECHNICIAN, ADMIN
- Automatic timestamps (createdAt, updatedAt)
- Password encryption using BCrypt

#### Customer Entity (`Customer.java`)
- One-to-one relationship with User
- Additional profile for users with CUSTOMER role
- Fields: id, user, defaultLatitude, defaultLongitude
- Automatically created when a user registers as CUSTOMER

#### OTP Verification Entity (`OtpVerification.java`)
- Stores OTP codes for account verification
- Fields: id, user, otpCode, otpType, expiresAt, isUsed, createdAt
- Types: REGISTRATION, PASSWORD_RESET, LOGIN
- 10-minute expiration period

### 2. **Repositories**
Created Spring Data JPA repositories:
- `UserRepository` - User CRUD operations with email/phone lookups
- `CustomerRepository` - Customer profile management
- `OtpVerificationRepository` - OTP management and verification

### 3. **DTOs (Data Transfer Objects)**
- `RegisterRequest` - Input validation for registration
  - Validates name (2-100 characters)
  - Validates email format
  - Validates phone number (10-15 characters)
  - Validates password (minimum 8 characters)
  - Validates role (required)

- `RegisterResponse` - Structured registration response
- `ApiResponse<T>` - Generic API response wrapper

### 4. **Services**
#### AuthService (`AuthService.java`)
- **Registration Logic**:
  - Validates unique email and phone number
  - Encrypts password using BCrypt
  - Creates user account
  - Automatically creates customer profile for CUSTOMER role
  - Generates 6-digit OTP
  - Stores OTP with 10-minute expiration
  - Returns comprehensive response with OTP (for testing)

### 5. **Controller**
#### AuthController (`AuthController.java`)
- **Endpoint**: `POST /api/auth/register`
- **Access**: Public (no authentication required)
- **Documentation**: Full Swagger/OpenAPI annotations
- **Error Handling**: 
  - 201 Created - Successful registration
  - 409 Conflict - Duplicate email/phone
  - 400 Bad Request - Validation errors

### 6. **Security Configuration**
#### SecurityConfig (`SecurityConfig.java`)
- Public access to `/api/auth/**` endpoints
- Public access to `/api/otp/**` endpoints
- Public access to Swagger UI (`/swagger-ui/**`, `/v3/api-docs/**`)
- BCrypt password encoder
- Stateless session management
- CORS enabled

### 7. **API Documentation**
#### SwaggerConfig (`SwaggerConfig.java`)
- Automatic API documentation generation
- Interactive testing interface
- Available at: `http://localhost:8080/swagger-ui.html`
- OpenAPI 3.0 specification

## 🗄️ Database Schema

The following tables are created automatically:

### users
```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    phone_number VARCHAR(255) NOT NULL,
    password VARCHAR(255) NOT NULL,
    role VARCHAR(255) NOT NULL CHECK (role IN ('CUSTOMER','TECHNICIAN','ADMIN')),
    is_verified BOOLEAN NOT NULL DEFAULT FALSE,
    is_blocked BOOLEAN NOT NULL DEFAULT FALSE,
    failed_login_attempts INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL
);
```

### customers
```sql
CREATE TABLE customers (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    user_id BIGINT NOT NULL UNIQUE,
    default_latitude NUMERIC(10,8),
    default_longitude NUMERIC(11,8),
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### otp_verifications
```sql
CREATE TABLE otp_verifications (
    id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    user_id BIGINT NOT NULL,
    otp_code VARCHAR(6) NOT NULL,
    otp_type VARCHAR(255) NOT NULL CHECK (otp_type IN ('REGISTRATION','PASSWORD_RESET','LOGIN')),
    expires_at TIMESTAMP NOT NULL,
    is_used BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMP NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```
